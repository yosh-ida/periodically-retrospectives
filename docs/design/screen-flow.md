# Screen Flow Design

## Overview

アプリはダッシュボードを起点に、反省点詳細、編集、振り返りへ遷移する。通知は `check-in` と `review` の 2 種類を持ち、各テーマは通知設定を参照しながら運用される。

## Routes

### `/`

- ダッシュボード
- アクティブな反省点一覧
- 通知設定の状態サマリー
- 直近の振り返り履歴サマリー

### `/themes/new`

- 反省点作成
- 通知設定参照の選択
- 必要に応じた通知設定の新規作成とその場での初期ルール編集

### `/themes/:id`

- 反省点詳細
- `check-in` 通知からの遷移先
- 直近の振り返り履歴を表示
- 振り返り結果の推移グラフを表示
- グラフの表示間隔切替を表示する
- `note` 付きデータ点の詳細確認導線を持つ

### `/themes/:id/edit`

- 反省点編集

### `/themes/:id/review`

- 振り返り入力
- `review` 通知からの遷移先

## Main User Flows

### 反省点作成フロー

1. ダッシュボードから作成ページへ移動する
2. 課題、原因、ゴールを入力し、必要なら通知設定との関連づけを行う
3. 通知設定を新規追加する場合は、その場で `check-in` / `review` の初期ルールを編集する
4. 保存後、ダッシュボードへ戻る

## UX Presentation Notes

- 画面内の見出し、補足文、CTA は一般ユーザー向けの文言に統一する
- UI には `Phase` や実装途中を示すラベルを表示しない

### `check-in` 確認フロー

1. `check-in` 通知を開く
2. 反省点詳細ページを表示する
3. 課題、原因、ゴールを確認する
4. 必要なら振り返り推移グラフを見て直近の変化を把握する

### `review` 振り返りフロー

1. `review` 通知を開く
2. 振り返りページで対象テーマの内容を確認する
3. 7 段階評価とメモを保存する
4. 詳細ページに戻るとグラフに新しい点が反映される

### 推移確認フロー

1. ユーザーが `/themes/:id` を開く
2. `そのまま` `週単位` `月単位` から表示間隔を選ぶ
3. 折れ線グラフで評価推移を確認する
4. `note` が付いた点を選択する
5. 単一点または対象期間にまとまったメモ内容を確認する

### 編集フロー

1. 詳細または一覧から編集ページへ移動する
2. 課題、原因、ゴール、通知設定との関連づけを更新する
3. 保存後、更新内容をダッシュボードと通知判定に反映する
